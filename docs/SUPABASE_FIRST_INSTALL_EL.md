# Πρώτη εγκατάσταση στο Supabase

Στις 2026-10-04 ο χρήστης ανέφερε εκτέλεση του [`INSTALL_ALL.sql`](../supabase/INSTALL_ALL.sql) και επιβεβαιώθηκε στο Table Editor η παρουσία των 14 αναμενόμενων πινάκων. Οι διευθύνσεις επιστροφής Auth αποθηκεύτηκαν και ο Google provider ενεργοποιήθηκε μέσω OAuth client στο υπάρχον Google Cloud project. Πραγματικό Google consent/login και reload με έναν λογαριασμό στο preview πέρασαν, με κενό dashboard και μηδέν ομάδες. Οι έλεγχοι απομόνωσης με δύο λογαριασμούς εκκρεμούν. Μην επανεκτελέσεις το SQL· τα βήματα 1–3 παρακάτω είναι αναφορά για νέα εγκατάσταση.

1. Άνοιξε το Supabase project που αντιστοιχεί στο URL του `.env.local` και πήγαινε στο **SQL Editor → New query**.
2. Άνοιξε το `supabase/INSTALL_ALL.sql`, αντίγραψε **όλο** το περιεχόμενο και πάτησε **Run** μία φορά. Περιλαμβάνει ιδιωτικές ομάδες, περιεχόμενο, ψηφοφορίες, σχόλια και ημερήσιο πρόγραμμα. Δεν περιέχει το πραγματικό ταξίδι ή στοιχεία μελών.
3. Περίμενε επιτυχή ολοκλήρωση. Το αρχείο εφαρμόζεται ως μία συναλλαγή. Αν εμφανιστεί σφάλμα, κράτησε το μήνυμα και μην εκτελείς μεμονωμένα κομμάτια ή διαγράφεις πίνακες. Αν υπάρχει ήδη schema της εφαρμογής, το αρχείο σταματά για έλεγχο.
4. Ρύθμισε **Authentication → URL Configuration** με το URL της εφαρμογής. Για το παρόν preview πρόσθεσε `http://127.0.0.1:4173/group-trip-planner/`. Για τη δημοσίευση πρόσθεσε `https://inbacklog.github.io/group-trip-planner/`.
5. Ο Google provider εμφανίζεται **Enabled** στο Supabase και το login στο preview λειτουργεί. Το [Google setup στο DEPLOYMENT](DEPLOYMENT.md#σύνδεση-με-google) καταγράφει τις ολοκληρωμένες ρυθμίσεις· δεν χρειάζεται δεύτερος OAuth client. Η εφαρμογή παραμένει **External / Testing**, με Publish app ανενεργό μέχρι ολοκλήρωση Branding. Τα Client ID/Secret αποθηκεύτηκαν μόνο στη ρύθμιση provider στο Supabase· δεν χρειάζεται να σταλούν στη συνομιλία. Εκκρεμούν αποσύνδεση και δοκιμή production URL. Για εγγραφές με email χρειάζεται κατάλληλη αποστολή email/SMTP.
6. Με δύο πραγματικούς λογαριασμούς και δοκιμαστικό περιεχόμενο, έλεγξε ότι νέος χρήστης ξεκινά άδειος, δεν βλέπει ξένη ομάδα και αποκτά πρόσβαση μόνο με πρόσκληση. Έλεγξε επίσης ότι η αφαίρεσή του ανακαλεί την πρόσβαση, ότι αλλάζει μόνο τη δική του ψήφο/σχόλιο και ότι οι αλλαγές προγράμματος ακυρώνουν προηγούμενες εγκρίσεις.
7. Μετά τους παραπάνω ελέγχους, συνδέσου με τον λογαριασμό σου, δημιούργησε την ιδιωτική παρέα και χρησιμοποίησε **Εισαγωγή** με το αρχείο `PRIVATE_NOT_FOR_GIT/OWNER_TRIP_IMPORT.ready.json`.

Η εισαγωγή διατηρεί τις παλιές ημέρες ως ιστορικό προσχέδιο στις πληροφορίες ταξιδιού. Δεν δημιουργεί αυτόματα ψήφους, σχόλια, προσωπικές εγκρίσεις ή επιβεβαιωμένες κρατήσεις. Το νέο κοινό πρόγραμμα συντάσσεται και εγκρίνεται από την παρέα μέσα στην εφαρμογή.

Το `INSTALL_ALL.sql` προορίζεται μόνο για πρώτη εγκατάσταση. Δημιουργείται από τις δύο migrations με `pnpm sql:bundle` και ελέγχεται με `pnpm sql:check`. Μην εκτελέσεις και το ενιαίο αρχείο και τις migrations ξεχωριστά. Μελλοντικό CLI migration push χρειάζεται πρώτα συμφωνία του migration history, όπως περιγράφεται στο DEPLOYMENT.
