# Πρόσθετα acceptance σενάρια — v2

**Κατάσταση: προδιαγραφές ελέγχων, ΟΧΙ εκτελεσμένα tests.** Ενσωματώνονται στα tests της αρχικής ανάθεσης· δεν αντικαθιστούν lint/build, αρχικά RLS/import/timezone/budget tests ή το `docs/ACCEPTANCE.md` αν υπάρχει.

## Test identities και περιβάλλον

Χρησιμοποίησε μόνο συνθετικά δεδομένα. Ομάδα Α: owner A1, member A2, member A3. Ομάδα Β: owner B1, member B2. Επιπλέον νέος χρήστης N και anon. Ταξίδια Α1/Α2 στην ίδια ομάδα και Β1 σε άλλη ομάδα. Δύο ανεξάρτητα browser contexts. Καμία πραγματική πρόσκληση, email ή seed στο online project χωρίς έγκριση.

RLS assertions εκτελούνται ως πραγματικοί anon/authenticated callers με τις ανάλογες sessions· όχι ως service-role/admin. Προνομιούχο setup μόνο για απομονωμένα local fixtures. Για κάθε test καταγράφεται command, backend, actual result και τυχόν limitation.

## C. Συμμετοχή ανά ταξίδι

Οι έλεγχοι ακολουθούν την προτεινόμενη v1 πολιτική: ιδιωτικότητα σε επίπεδο παρέας, συμμετοχή χωριστά από δικαιώματα ανάγνωσης.

| ID | Δοκιμή | Αναμενόμενο |
|---|---|---|
| PAR-01 | A2 ενεργό μέλος, χωρίς `going` στο Α1 | Βλέπει κοινό περιεχόμενο της ομάδας αλλά δεν υπολογίζεται σαν ταξιδιώτης/ενεργός ψηφοφόρος. |
| PAR-02 | A2 going στο Α1, όχι στο Α2 | Totals, approvals και κόστος δεν αναμειγνύονται. |
| PAR-03 | Owner A1 not_going | Διαχειρίζεται επιτρεπόμενο πρόγραμμα χωρίς αυτόματη προσμέτρηση σε ταξιδιώτες. |
| PAR-04 | A2 αλλάζει status A3 ή forged user ID | Η μη εξουσιοδοτημένη εγγραφή απορρίπτεται στη βάση. |
| PAR-05 | B1 εισάγεται σε trip_participants του Α1 με γνωστά UUIDs | Απόρριψη· η ιδιότητα συμμετέχοντα δεν παρακάμπτει membership. |
| PAR-06 | Going → not_going | Παλιές προτιμήσεις δεν μετρούν ως ενεργές και οι εγκρίσεις δεν μένουν σιωπηρά τρέχουσες. |
| PAR-07 | Μηδέν going ταξιδιώτες ή άγνωστη σύνθεση | Καθαρή κατάσταση, όχι division by zero ή αυθαίρετο κόστος ανά τέσσερα άτομα. |
| PAR-08 | Αφαίρεση A2 από ομάδα με ανοικτό session | Δεν έχει επόμενα reads/writes/subscriptions, ακόμη και με παλιό trip_participants record. |
| PAR-09 | Αλλαγή συμμετοχών ενώ εμφανίζεται σύνοψη | Refresh/realtime και version handling χωρίς σιωπηρά stale totals. |

## Αναφορά ελέγχου που πρέπει να παραδώσει το Codex

Αρχείο `docs/TEST_REPORT.md`: εντολή, environment, test IDs, αποτέλεσμα, αποδεικτικό/σύντομο output και περιορισμός. `PASS` μόνο όταν έτρεξε επιτυχώς. `FAIL` όταν έτρεξε και απέτυχε. `NOT RUN` όταν δεν υπήρχε Docker/browser/network/config/έγκριση. Ξεχώρισε unit/mock από πραγματικό local Supabase integration και από εγκεκριμένο remote check.

Η ύπαρξη αυτών των σεναρίων στο ZIP δεν αποτελεί έλεγχο ή πιστοποίηση του app.
